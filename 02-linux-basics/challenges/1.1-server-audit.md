4. What is in /sys? How does it differ from /proc?

ls /sys
block  bus  class  dev  devices  firmware  fs  hypervisor  kernel  module  power

_____________


Feature		/proc (Procfs)	/sys (Sysfs)
Primary Focus	Running processes (PIDs) and system-wide software stats.	Hardware devices, buses, drivers, and kernel subsystems.
Structure		A mix of process ID numbers and flat system files.		A strict, hierarchical tree mirroring the physical hardware layout.
Historical Origin		Created first in early Unix/Linux to inspect process memory.		Introduced in Linux 2.6 to separate device data from /proc.
Typical Use Case		Checking RAM (meminfo) or tracking active app IDs.		Changing CPU fan speeds, network card settings, or disk power modes.

Inode = the library card. It holds owner, permissions, size, timestamps, link count and where the content lives. It does not hold the file name. Names live in the folder.

Command	- What it shows
ls -i <file>	the inode number
ls -il <path>	inode, link count, size and more
df -i /	inode usage of the disk (IUse%)
df -h /	space usage of the disk (Use%)

Hard link = a second name for the same card.

ln original.txt hard.txt
Same inode, link count goes up (1 to 2).
A change through either name shows in both.
rm removes one name. The content is gone only when the count hits 0.

Symbolic link = a signpost to a name.

ln -s original.txt soft.txt
Own inode, starts with l, shows ->.
If the target name is deleted, it becomes a dangling symlink (No such file or directory).
 
                              Hard link	             Symbolic link
Inode	                 same as the original       	its own
Survives rm original?	         yes	              no (dangling)
Link count	                   goes up	               unchanged

Inode exhaustion: all cards are used (IUse% 100%), so no new files can be created even if Use% shows free space. Error: No space left on device.
